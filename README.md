# AIVOXFLOW

**Intelligence in Motion.** A fast, source-first publication about AI tools, tutorials, software, automation and verified AI news.

Static site, zero runtime dependencies, no third-party scripts. Every page is generated by `site/build.mjs` and published as plain HTML, CSS and one small JS file.

---

## Quick start

```bash
node --version          # >= 20.11
npm run build           # generate dist/
npm run dev             # preview http://127.0.0.1:8130
npm test                # 106 structural / SEO / a11y / budget checks
npm run test:responsive # 31 layout + keyboard checks (needs local Edge)
```

There is nothing to install: the project has no dependencies and no lockfile.

## Environment

All configuration is environment-driven. Nothing is required for a local preview; production needs at least `AIVOXFLOW_SITE_URL`.

| Variable | Required | Effect when set |
| --- | --- | --- |
| `AIVOXFLOW_SITE_URL` | production | Enables canonical URLs, `sitemap.xml`, `robots.txt`, RSS + JSON Feed, absolute OG images and structured data. When absent, all of it is **omitted** rather than guessed. |
| `AIVOXFLOW_BASE_PATH` | no | Sub-path deployment (e.g. `/my-repo` on GitHub Pages). Applied to every internal URL **and** to canonicals/sitemap. |
| `AIVOXFLOW_CONTACT_EMAIL` | no | Publishes a real `mailto:` on `/contact/`. When empty, the page says plainly that no channel is open. |
| `AIVOXFLOW_NEWSLETTER_ACTION` | no | Turns `/newsletter/` into a working form posting to that endpoint. |
| `AIVOXFLOW_ANALYTICS_SCRIPT` / `_ENDPOINT` | no | Injects one measurement script and widens the CSP for that origin only. Nothing loads when unset. |
| `AIVOXFLOW_LANGUAGE` / `_LOCALE` | no | `<html lang>` and Intl formatting. Defaults to `en` / `en_US`. |

See [docs/MEASUREMENT.md](docs/MEASUREMENT.md) and [docs/I18N.md](docs/I18N.md).

## Content model

```
site/data/
  articles/*.json   one file per article
  categories.json   six topics
  tools.json        verified tool entries
  pages.json        about / contact / legal pages (Markdown body)
  authors.json      author entities used by bylines and schema
```

An article requires `slug`, `title`, `description`, `category`, `published`, `author`, `body`. Optional: `updated`, `tags`, `featured`, `seoTitle`, `disclosure`.

The build **fails** on missing fields, unknown categories, non-ISO dates, duplicate slugs, duplicate titles or duplicate descriptions — a half-filled article can never reach production.

Markdown supports `##`–`####`, nested lists, blockquotes, fenced code, GFM tables with alignment, images (width/height read from the file), `---`, bold, italic, inline code and links. Raw HTML is escaped first and never passed through.

### Adding an article

```bash
cp site/data/articles/01-choose-an-ai-writing-tool.json site/data/articles/07-my-topic.json
# edit slug/title/description/published/body, then:
npm run build && npm test
```

Social cards are pre-rendered PNGs in `site/assets-src/og/`. After adding an article run `npm run og` to generate its card (needs Edge or Chrome once; the PNG is committed so builds never need a browser).

## Build pipeline

1. Writes everything into `dist.tmp/`.
2. Fingerprints `site.css` and `site.js` (SHA-256, 10 chars) and links the hashed names.
3. Renders 27 routes, the search index, sitemap, feeds and `_headers`.
4. **Swaps** `dist.tmp/` into `dist/` only when every page succeeded; the previous tree is kept until the swap completes.

A failed build therefore never leaves a half-published site behind, and the previous deploy stays intact.

## Deployment

The output is plain static files — any host works.

- **Netlify / Cloudflare Pages**: `netlify.toml` is included; `dist/_headers` is generated with the CSP, HSTS and immutable asset caching.
- **Vercel**: `vercel.json` mirrors the same headers (Vercel ignores `_headers`; keep the two in sync).
- **GitHub Pages**: set `AIVOXFLOW_BASE_PATH` to the repository name; note that GitHub Pages cannot send custom headers.

Always build with `AIVOXFLOW_SITE_URL` set, otherwise the sitemap, feeds and canonicals are intentionally absent.

**Production guard:** `site/config.mjs` refuses to build when the environment looks like a
production host (`AIVOXFLOW_ENVIRONMENT=production`, or the `NETLIFY`/`VERCEL` markers) and
`AIVOXFLOW_SITE_URL` is empty — a forgotten dashboard setting can no longer publish a site
without canonicals, sitemap, robots.txt or feeds. Local previews are unaffected. Set the real
launch URL in the host environment before the first deploy.

### Automatic deployment (FTP, no database)

`deploy/deploy.mjs` replaces the whole manual File Manager routine — still nothing to
install: the site is static HTML, so there is no database and no PHP anywhere in the
pipeline.

```bash
# one-time setup: set an FTP password in hPanel (Files -> FTP Accounts), then
cp deploy/.ftp.env.example deploy/.ftp.env   # fill in; gitignored, never committed

node deploy/deploy.mjs --dry-run   # show the upload plan (no network)
node deploy/deploy.mjs             # build -> back up live .htaccess -> upload -> live checks
```

The script refuses to upload a preview build, backs up whatever `.htaccess` is live into
`deploy/backup-<timestamp>/` before replacing it, and finishes with live smoke tests
(sitemap host, real 404, trailing-slash redirect, HSTS, immutable asset cache).

## Content agents

Article production is a separate, auditable pipeline in [`agents/`](agents/README.md): research →
brief → draft → fact-check → SEO → artwork → editorial QA. It runs offline with no keys and
refuses to publish anything the gates cannot defend.

```bash
npm run agent -- --topic "How to choose an AI writing tool" --category ai-tools
npm run agent:demo     # offline end-to-end run against a fixture
npm run agent:doctor   # check keys and list the models your key can use
npm run agent:list     # every job and its state
```

Nothing reaches `site/data/articles/` without `--publish` after a full gate pass.

### Continuous, scheduled publishing

```bash
npm run plan              # fill the next slots from the topic backlog
npm run schedule:due      # what is ready to be written now
npm run schedule          # generate what is due, then rebuild dist/
npm run schedule:daemon   # keep checking every 30 minutes
```

Articles are written ahead of their slot and **dated for it**; the build hides future-dated
articles, so a nightly cron can never leak tomorrow's piece. Two GitHub Actions workflows ship
ready: `content.yml` (daily generation) and `publish.yml` (rebuild at peak windows). See
[docs/SCHEDULING.md](docs/SCHEDULING.md) for peak-time configuration and host setup.

## Repository layout

```
site/
  build.mjs        generator (routes, SEO, feeds, headers, atomic swap)
  config.mjs       env-driven configuration
  lib/             html layout, markdown, content loading, image sizes, assets
  styles/site.css  all styles (tokens prepended at build)
  scripts/site.js  ~8 KB progressive enhancement (nav, search, copy link)
  data/            content
  assets-src/      OG cards + per-article artwork (committed, no browser needed to build)
  og/              social-card generator
agents/            content pipeline: 6 agents, prompts, gates, image renderer
brand/             logo, icons, tokens, brand guide
tests/             structural suite + responsive/keyboard suite
docs/              plans, audits, QA screenshots, operational notes
content/           agent working state — job logs and drafts (gitignored)
```

## Editorial rules

The operating rules in [AGENTS.md](AGENTS.md) are binding: no unverified claims, no fabricated testing, no invented people or quotes, no affiliate links, no autonomous publishing without an approved quality gate. Corrections are published on `/corrections/`.
