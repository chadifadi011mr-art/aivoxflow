# Internationalisation — current state and how to add a language

## What exists today

- `<html lang>` and `<html dir>` come from `config.language` (currently `en` / `ltr`).
- `config.locales` lists the languages that are **actually published**. With one entry the
  language switcher and the `hreflang` block stay inert — the site never emits hreflang
  annotations for translations that do not exist.
- Dates go through `formatDate(iso, locale)` (Intl), so a locale change reformats them.
- `slugify()` is Unicode-aware: Arabic, Cyrillic and CJK headings produce stable anchor ids
  instead of empty strings.
- The font stacks already declare `"Noto Sans Arabic"` / `"Noto Naskh Arabic"` fallbacks, and
  the Latin WOFF2 subsets use `unicode-range`, so non-Latin text falls through cleanly.

## What is *not* done

- UI strings are still hard-coded in English inside `site/build.mjs` and `site/lib/html.mjs`.
  Extracting them into `site/i18n/<locale>.json` is the first task of a real translation pass.
- No translated content exists, and none should be published until a human reviews it.

## Adding a locale (checklist)

1. **Routing.** Give each locale a stable prefix: `/en/`, `/es/`, `/fr/`, `/de/`, `/ar/`, `/pt/`.
   English currently lives at the root; either keep the root as the default and mirror the
   others under prefixes, or move everything under `/en/` and add a redirect map from the old
   URLs. Do not switch based on IP.
2. **Config.** Add `{ code, label, dir }` to `config.locales` and set `dir: 'rtl'` for Arabic.
   `hreflangTags()` and `x-default` start emitting automatically.
3. **Content.** Articles need a `lang` field and a translation group id so equivalents can be
   linked. Only link URLs that are genuine equivalents — a partial translation must not claim
   hreflang for pages it does not cover.
4. **Strings.** Extract the UI strings, translate them, and check line lengths: German and
   Arabic run longer and will break tight layouts.
5. **Sitemap.** Add `xhtml:link` alternates once more than one locale is indexable.
6. **Quality gate.** No machine translation goes live without a native review pass. A missing
   translation must 404 honestly rather than silently serve English under a Spanish URL.

## Acceptance criteria for "locale shipped"

- Every indexable page has a self-referencing canonical and reciprocal `hreflang`.
- The language switcher is visible, keyboard reachable and preserves the current page.
- Dates, numbers and units are localised, not just body text.
- `npm test` passes with the new locale included in the sitemap checks.
